Before you start Primer · 03

First, the definition that matters

What an AI agent
actually is.

Most content on this topic conflates three different things: chatbots, prompts, and agents. Here's the line that separates them.

The one-liner

An AI agent is a system with a defined role, the tools to act without asking, and the memory to apply both consistently over time.

Every real agent has three components: (1) instructions, the role, behavior, and constraints. (2) tools, what it can actually do in the real world: send email, query APIs, read files, browse, execute code. (3) memory, the examples, rules, and prior context it reads before every action.

"Isn't this a chatbot?" A chatbot answers questions you type. An agent has a job description, the tools to execute it, and the memory to stay consistent across runs. You configure it once. It keeps working.

"Do I need to code?" No. Modern platforms (Claude Desktop with MCP, ChatGPT with Custom GPTs and Actions, n8n, Zapier) let you build production agents from a browser. Code is the upgrade path, not the entry fee.

"What does a real agent do?" Triage your inbox and surface only what needs you. Draft external replies in your voice. Run a daily report from Stripe and GA. Research inbound leads and queue personalized first touches. Publish content on schedule. Anything with a repeatable process and a measurable outcome.

Set expectations

Your first agent owns one lane, not your business. Teams shipping serious AI products did not start with an omni-agent. They started with one narrow role done better than a human, then stacked more. That's the path.

Step 01 of 07 Define the role · 04

STEP 01

Define the role.
Not the task.

The difference between a useful agent and a clever toy is whether it was built around a role or a task. Tasks are brittle: the inputs change and the agent breaks. Roles scale: the agent owns a function, not a single job.

A task-based agent does one isolated thing: "rewrite this email." A role-based agent owns an outcome: "you are my inbox editor. You triage, draft replies, and escalate the three messages I need to see." The second agent keeps working when the inputs change next week.

The role brief. Answer all four.
  • Who does it replace? Name the human role. Inbox editor. Research analyst. LinkedIn ghostwriter. Pipeline SDR. Operations reporter.
  • What outcome does it deliver? One sentence. "A sorted inbox with three escalations and ten drafted replies by 9am."
  • When does it run? Manual, scheduled, or triggered by an event. Pick one for v1.
  • How is success measured? "Zero inbox by noon." "Five research briefs per week." Measure or it's theater.

Step 02 of 07 Choose the stack · 05

STEP 02

Choose the stack.
Ignore the rest.

There is no best stack. There is a best stack for your role, budget, and technical comfort. The trap is picking the most powerful option before you know what you're building.

  1. Personal assistant with tools. Claude Desktop plus MCP servers. Free on Claude Pro. Fastest path to a real agent that can read your files, email, and calendar. Ceiling: your laptop stays on.
  2. Shareable branded assistant. OpenAI Custom GPT with Actions. $20/mo. Shareable link. Solid ceiling for most SMB use cases. Weaker on file handling than Claude.
  3. Workflow automation agent. n8n (self-host, powerful) or Zapier/Make (cloud, simpler). Best when the work is a pipeline with multiple apps, not a chat. Runs on a schedule or trigger.
  4. Developer stack. Claude Agents SDK or OpenAI Assistants API. Full control, custom tools, production-grade deployments. Requires code. Ceiling: anything.
The recommendation for v1

Start with Claude Desktop + MCP, or n8n.

Both deliver a real agent with real tools in one focused afternoon. The role and the system prompt transfer between stacks later. What you're building now is the blueprint. The platform is just a substrate.

What to ignore for your first build

Multi-agent frameworks (CrewAI, AutoGen), vector databases (Pinecone, Weaviate), and custom orchestration. All real, all powerful, and all wrong for agent #1. Ship the single-agent version first. Graduate to frameworks when you've hit their ceiling.

Step 03 of 07 System prompt · 06

STEP 03

Write the system prompt.
The constitution.

The system prompt is what the agent reads before every action. Role, constraints, format. A strong one makes a mid-tier model feel senior. A weak one makes a frontier model feel like a lazy intern.

# ROLE You are [role], a senior [function]. Sole job: [outcome]. # TOOLS Access: [list tools]. Use them without asking inside scope. # HOW I WORK - Direct. No hedging, no preambles, no apologies. - Voice: [traits]. Never use: [banned patterns]. - When in doubt, act. When out of scope, escalate. # OUTPUT FORMAT 1. The deliverable (lead with it, no setup) 2. What you used to reach it (one line) 3. Anything that needs attention (flag, don't bury) # SCOPE IN: [3-5 things the agent owns] OUT: [3-5 things it escalates] # HARD LIMITS You do not [list 2-3 refusals].
Where it goes

Claude Desktop: "Project instructions." Custom GPTs: "Instructions." n8n AI Agent: "System message." Paste the filled-in version. Save. The agent has a constitution.

Step 04 of 07 Connect the tools · 07

STEP 04

Connect the tools.
This is the difference.

Without tools, you have an eloquent chatbot. With tools, you have an agent. This is the step most people skip, and it is the single biggest determinant of whether your agent actually does work or just talks about it.

A tool is anything the agent can invoke to take a real action: read a file, search the web, send an email, query an API, post to a channel, execute code, browse a site. Start with three, chosen to match the role.

The starter toolset. Pick three.
  • Web search. So the agent can research beyond its training cutoff. Claude has this native. GPT has it via browsing.
  • File or document access. So it can read the project knowledge you'll attach in Step 05, plus anything you drop mid-task.
  • Email, Slack, or calendar. So it can act on your behalf. Inbox editor needs Gmail. SDR agent needs email plus LinkedIn. Reporting agent needs calendar for context.
  • API call. So it can pull from or write to your stack: Notion, Airtable, Stripe, Sheets, your CRM. Most modern tools expose a clean API.
How to wire tools, by stack

Claude Desktop: install MCP servers (gmail, slack, filesystem, brave-search). Settings, Developer, Edit Config. Five minutes per server.

Custom GPT: Actions tab. Paste the OpenAPI spec for whatever service you want. Most SaaS tools publish one.

n8n, Zapier, Make: add nodes. Every major app has a native integration. Drag, authenticate, connect.

Step 05 of 07 Memory · 08

STEP 05

Give it memory.
Context compounds.

An agent with no memory repeats the same mistakes every run. An agent with memory compounds. It gets sharper weekly until it knows your business, your voice, and your constraints better than a new hire.

The three memory layers
  • System prompt (never changes). Role, constraints, format. Written once in Step 03.
  • Project knowledge (updated weekly). Examples, style guides, brand rules, customer docs. Lives in the platform's knowledge or project files field.
  • Working context (per task). The notes, thread, or raw input you drop in at run time.
What to load as project knowledge
  • Five to ten examples of the exact output you want. Best emails, posts, briefings. Concrete beats abstract.
  • A voice guide. One page. Words you use, patterns you avoid, format you expect.
  • Business context. Audience, positioning, product, pricing. One paragraph each.
  • Hard rules. Claims it cannot make. Features it cannot reference. Phrases off-limits.
Curate, don't dump

Five excellent examples beat fifty mediocre ones. The agent learns from what you show it. Replace old examples as your bar moves.

Step 06 of 07 Trigger · 09

STEP 06

Trigger the first run.
Then run it tomorrow.

The moment an agent runs without you kicking it off manually is the moment it becomes an agent in practice, not just in name. You don't have to automate on day one. But plan for it from day one.

  1. Manual. You open the agent and paste the input. Fine for v1. Fastest way to validate the role before you automate.
  2. Scheduled. Runs at 7am weekdays. Runs hourly. Runs Monday mornings. Configured in n8n, Zapier, or a cron. Ideal for reporting, daily digests, weekly pipelines.
  3. Event-triggered. Email lands, agent runs. Form submits, agent runs. PR opens, agent runs. Webhooks or native platform triggers.
  4. Conversational handoff. You or a teammate mention the agent in Slack, Discord, or a shared thread. It picks up, handles, replies in-channel.
# TASK [one-line description of what you want delivered] # INPUT [paste raw source: notes, thread, data, messy draft] # CONSTRAINTS - [anything unique to this run: deadline, length, audience] DELIVER.
Reduce friction to one paste

Save the template as a text snippet: Raycast, Alfred, TextExpander, or a pinned note. One paste to trigger a run. Friction is what kills the habit, and the habit is what makes the agent worth building.

Step 07 of 07 Harden · 10

STEP 07

Measure. Harden.
Then scale.

Your first agent will hit 70% quality out of the gate. The gap between 70% and production-grade is entirely about supervision, promotion, and guardrails. This is the step that separates a weekend project from a real operator on your team.

  1. Measure. Track one number that proves the agent works. Time saved per week. Drafts shipped. Leads triaged. Pick one. Write it down. Check it weekly.
  2. Harden. Every time you correct an output, ask: one-off or pattern? If it's a pattern, promote the correction into the system prompt or project knowledge. The agent compounds. You stop correcting the same things twice.
  3. Scale wider. Once the agent runs reliably with minimal correction, give it more tools or expand its scope inside the same role.
  4. Scale deeper. Spin up agent #2 for an adjacent role. Inbox editor, then calendar assistant. Content strategist, then distribution agent. Role by role, not all at once.
Guardrails before autonomy

An agent taking real actions needs real guardrails. Before you let any agent act externally: require human approval on the first 20 runs, scope tools narrowly (read-only until the agent earns write access), log every action somewhere auditable, and set a kill switch you can trigger in one click if something looks off.

The compounding principle

One working agent becomes five. The second takes half as long. The fifth takes an afternoon. Stack them and you start every Monday with a silent team running the repetitive work. That is the play. This playbook is step one.
