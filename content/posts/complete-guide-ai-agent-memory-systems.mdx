<h2 id="context-windows-the-simplest-memory">Context Windows: The Simplest Memory</h2><p>Every LLM has a context window. Think of it as short-term memory. Claude Opus 4 has a 200K token context window (about 150,000 words). GPT-4o has 128K tokens. Gemini 1.5 Pro goes up to 2M tokens.</p><p>The context window includes everything: your system prompt, the conversation history, tool results, and the model's own responses. When it fills up, old messages get dropped or compressed.</p><h3 id="context-window-sizes-in-2026">Context Window Sizes in 2026</h3>

<p>Context window memory is fast and simple. But it has two problems. First, it disappears when the session ends. Second, it gets expensive when you stuff it full of context on every request.</p><h2 id="rag-teaching-your-agent-to-search">RAG: Teaching Your Agent to Search</h2><p>RAG stands for Retrieval Augmented Generation. Instead of cramming everything into the context window, you store your knowledge in a searchable database. When the agent needs information, it searches for relevant chunks and pulls only what it needs.</p><h3 id="how-rag-works-step-by-step">How RAG Works (Step by Step)</h3><ol><li><strong>Chunk your documents.</strong> Break them into pieces of 200-500 tokens each. Overlap by 50 tokens between chunks to preserve context.</li><li><strong>Embed the chunks.</strong> Use an embedding model (like OpenAI's text-embedding-3-small or Cohere's embed-v3) to convert each chunk into a vector (a list of numbers that represents the meaning).</li><li><strong>Store in a vector database.</strong> Pinecone, Weaviate, Qdrant, ChromaDB, or Supabase pgvector. Each chunk gets stored with its vector and the original text.</li><li><strong>Query at runtime.</strong> When your agent needs information, embed the question, search for the nearest vectors, and inject the matching chunks into the context window.</li><li><strong>Generate with context.</strong> The LLM now has the relevant knowledge right there in its prompt. It answers based on your specific data.</li></ol><h3 id="rag-vs-fine-tuning">RAG vs Fine-Tuning</h3><p>People ask me this constantly. Fine-tuning changes the model's weights. RAG changes what the model sees. For 95% of business use cases, RAG is better because:</p><ul><li>You can update the knowledge base instantly (no retraining)</li><li>You can see exactly what information the agent used (transparency)</li><li>It costs a fraction of fine-tuning</li><li>It works with any model (not locked to one provider)</li></ul><p>Fine-tuning is better only when you need to change the model's behavior or writing style fundamentally. For knowledge and data, always use RAG.</p><h2 id="vector-databases-where-agent-memory-lives">Vector Databases: Where Agent Memory Lives</h2><p>A vector database is a specialized database designed to store and search vectors (numerical representations of text, images, or other data). <p>My recommendation for beginners: start with ChromaDB locally. It installs with <code>pip install chromadb</code> and requires zero configuration. When you need production scale, move to Pinecone or Supabase pgvector.</p><h2 id="file-based-memory-the-simplest-permanent-memory">File-Based Memory: The Simplest Permanent Memory</h2><p>Not everything needs a vector database. For many agent use cases, file-based memory works perfectly. Claude Code uses this approach. It reads and writes markdown files in a <code>.claude/</code> directory.</p><p>Here is how I structure file-based memory for my agents:</p><pre><code>memory/
  user-preferences.md      # Voice, style, tone preferences
  client-profiles.json     # Client data and history
  task-history.json        # What the agent has done before
  knowledge-base/          # Reference docs the agent can search
    brand-guidelines.md
    product-catalog.md
    faq.md</code></pre><p>The agent reads these files at the start of each session. It writes updates back after completing tasks. Simple. Reliable. No database to manage.</p><p>For security considerations with persistent memory, check my <a href="https://aiagentsfirst.com/">security</a> guide.</p><h2 id="building-a-memory-system-my-practical-framework">Building a Memory System: My Practical Framework</h2><h3 id="step-1-identify-what-needs-to-be-remembered">Step 1: Identify What Needs to Be Remembered</h3><p>Not everything should go into memory. Focus on information that changes the agent's behavior or output quality. User preferences, past decisions, client data, and domain knowledge are high value. Raw conversation logs are low value.</p><h3 id="step-2-choose-the-right-storage">Step 2: Choose the Right Storage</h3><ul><li>Fewer than 100 documents: file-based memory</li><li>100-10,000 documents: ChromaDB or SQLite with FTS</li><li>More than 10,000 documents: Pinecone, Weaviate, or pgvector</li></ul><h3 id="step-3-build-the-retrieval-pipeline">Step 3: Build the Retrieval Pipeline</h3><p>Your retrieval pipeline should do three things: search for relevant context, rank results by relevance, and format them for injection into the prompt. Keep it simple. Complexity kills reliability.</p><h3 id="step-4-test-with-real-queries">Step 4: Test With Real Queries</h3><p>The most common RAG failure is retrieving irrelevant chunks. Test with 20-30 real questions your agent will receive. Check what gets retrieved. Adjust chunk size and overlap if the results are off.</p><h2 id="advanced-techniques-i-actually-use">Advanced Techniques I Actually Use</h2><h3 id="hybrid-search">Hybrid Search</h3><p>Combine vector search (semantic similarity) with keyword search (exact matches). This catches cases where pure semantic search misses specific terms like product names or error codes.</p><h3 id="memory-compression">Memory Compression</h3><p>Long conversation histories eat tokens. I use a summarization step that compresses old messages into a 200-word summary. The agent gets the full last 10 messages plus the compressed history of everything before that.</p><h3 id="memory-prioritization">Memory Prioritization</h3><p>Not all memories are equal. I tag memories with importance levels. Critical preferences (like "never send emails without approval") always get included. Nice-to-have context (like "client prefers blue") only gets included when there is room in the context window.</p><p>These techniques work with any of the <a href="https://aiagentsfirst.com/">platforms</a> I have tested.</p><h3 id="join-500-ai-agent-builders">Join 500+ AI Agent Builders</h3><p>Get templates, workflows, and live build sessions inside our free Skool community.</p><p><a href="https://www.skool.com/e-com-freedom-amazon-tiktok-4556?ref=aiagentsfirst.com">Join Free on Skool →</a></p><h2 id="common-mistakes-with-agent-memory">Common Mistakes With Agent Memory</h2><ul><li><strong>Storing too much.</strong> More memory is not always better. Irrelevant context confuses the agent and wastes tokens.</li><li><strong>Never cleaning up.</strong> Outdated memory causes stale behavior. Review and prune your knowledge base monthly.</li><li><strong>Ignoring chunk size.</strong> Chunks that are too large include irrelevant info. Chunks that are too small lose context. 300-500 tokens is the sweet spot for most use cases.</li><li><strong>Skipping evaluation.</strong> If you do not measure retrieval quality, you are guessing. Track precision and recall on a test set.</li></ul><h2 id="faq">FAQ</h2><h3 id="what-is-the-cheapest-way-to-add-memory-to-an-ai-agent">What is the cheapest way to add memory to an AI agent?</h3><p>File-based memory costs nothing. Write a JSON or markdown file. Have your agent read it at startup. This works for personal agents and small businesses. I use this approach for half my agents.</p><h3 id="how-much-does-a-vector-database-cost">How much does a vector database cost?</h3><p>ChromaDB is free and open source. Pinecone's free tier handles 100K vectors. Supabase's free tier includes pgvector. You will not pay anything until you scale past thousands of documents.</p><h3 id="do-i-need-rag-if-i-am-using-claude-with-200k-context">Do I need RAG if I am using Claude with 200K context?</h3><p>If your knowledge base fits in 200K tokens (about 150,000 words), you can skip RAG and just stuff it in the context window. But you will pay for those tokens on every single request. RAG is cheaper at scale.</p><h3 id="can-i-use-rag-with-local-models">Can I use RAG with local models?</h3><p>Yes. ChromaDB works perfectly with local embedding models and local LLMs. Check my <a href="https://aiagentsfirst.com/">local-models</a> article for setup details.</p><h3 id="how-do-i-know-if-my-rag-system-is-working-well">How do I know if my RAG system is working well?</h3><p>Ask it 20 questions you know the answers to. If it gets 17+ right, your RAG is solid. If it is below 15, your chunking strategy or embedding model needs work.</p>
