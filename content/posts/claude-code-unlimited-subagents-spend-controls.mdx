<h1>Claude Code August 2026: Unlimited Subagents, Spend Controls, and What It Costs You</h1>

<p class="lede">Claude Code shipped two releases on August 8 (v2.1.225 and v2.1.226) and removed the 200-subagent-per-session cap on August 4 (v2.1.221). The cap removal unlocks longer autonomous sessions -- but without guardrails, costs can escalate fast. Here is what changed, what it costs, and the four limits you should set today.</p>

<p>Two releases before 3am UTC this morning. A cap removal four days ago that most builders have not processed yet. If you are running any kind of multi-agent workflow on Claude Code, this week matters -- not because anything is broken, but because the cost equation just changed.</p>

<h2>What shipped in v2.1.225 and v2.1.226?</h2>
<p>Claude Code shipped v2.1.225 and v2.1.226 both on August 8, 2026. The bigger of the two is v2.1.225, which adds gateway spend-limit support -- when you hit a spend cap, Claude Code now surfaces the cap amount, its reset time, and any message your operator set. v2.1.226 is bug fixes and reliability improvements only.</p>
<p>The full v2.1.225 changelog is substantial. Beyond spend-limit visibility, it ships a workspace trust prompt for <code>claude agents</code> in untrusted directories (matching the behavior <code>claude</code> already had), several Remote Control fixes, a VSCode focus-view fix, and a patch for transient 401 errors that were breaking headless sessions on OAuth token refresh. The MCP OAuth 401 failure on macOS after keychain read timeouts is also fixed in this release.</p>
<p>Neither of today's releases introduced the subagent cap removal -- that landed August 4 in v2.1.221. But the combination of unlimited spawns (v2.1.221) and visible spend limits (v2.1.225) is the real story this week, and the two changes are designed to work together.</p>

<h2>What does removing the 200-subagent cap actually mean?</h2>
<p>Before v2.1.221, Claude Code enforced a hard 200-subagent-per-session limit. Long-running orchestration sessions -- think overnight research agents, multi-day CI pipelines, or large codebase migrations -- would hit 200 spawns and stop accepting new agents. As of August 4, that ceiling is gone.</p>
<p>Three limits still govern subagent fan-out. Concurrency stays capped at 20 simultaneous subagents (set via <code>CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS</code>, default 20). Spawn depth stays at 3 levels (set via <code>CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH</code>). The per-session total limit is the one that was removed. You can now spawn 500, 1,000, or theoretically unlimited subagents in a single session -- bounded only by your token budget and the concurrency ceiling.</p>
<p>For most builders, this is a meaningful unlock. The 200-subagent wall was hitting large-scale refactors and multi-step research pipelines in production. Removing it means a session can run as long as the task demands without hitting an arbitrary ceiling.</p>

<h2>The cost math on unlimited subagent sessions</h2>
<p>Removing the spawn cap does not change token pricing. What it does is remove the artificial ceiling that was also acting as a cost brake. At an average of 3 per developer per active day on a single session, running five concurrent subagents drains your token quota five times faster -- and on a Pro plan, the 5-hour rolling window empties in under an hour at full concurrency.</p>
<p>The cost scales predictably by parallelism level. Running three parallel agents lands at roughly 0 to 0 per day (00 to 00 per month at 20 working days). Pushing to five to ten parallel agents runs 0 to 30 per day -- ,000 to ,600 per month. These are median estimates based on typical context sizes; large codebase tasks push higher.</p>
<p>The tail risk is real. One financial services team reported 7,000 in token costs over three days after 23 subagents continued analyzing code unattended. That incident happened before the 200-cap removal, on the old guardrails. With the cap gone and longer sessions possible, that kind of runaway spend is now easier to hit accidentally.</p>
<p>Before v2.1.217 (July 21), the <code>--max-budget-usd</code> flag on background agents was not actually enforced -- it was logged but did not halt execution. That was fixed in v2.1.217. If you are running background agents and pinned below v2.1.217, the budget flag is not protecting you.</p>

<h2>How the new gateway spend-limit support works</h2>
<p>The v2.1.225 spend-limit feature surfaces gateway-enforced spend caps directly inside Claude Code. When you hit a limit, instead of a generic error, you see the cap amount, the exact reset time, and any custom message your gateway operator set. This requires the gateway to also be running v2.1.225 or later.</p>
<p>If you are running Claude Code through an enterprise AI gateway -- Bifrost, Cloudflare AI Gateway, LiteLLM, Kong, or OpenRouter are the common options -- and your IT or finance team has set per-user or per-team spend thresholds, those limits now surface cleanly in the Claude Code UI rather than as opaque 429 or rate-limit errors. The reset time visibility is particularly useful for developers who need to plan work around budget windows.</p>
<p>For teams without a gateway layer, this specific feature does not apply yet. Anthropic's native billing console shows total organizational spend but does not currently offer granular per-session, per-developer, or per-project caps out of the box. An enterprise AI gateway is still required to get that granularity. Claude Enterprise spend controls (launched July 2) offer model-level entitlements and spend-threshold alerts for IT and finance teams at the organizational level.</p>

<h2>The four limits to set before you ship long-running agents</h2>
<p>With the per-session cap gone, you need to set your own cost ceiling explicitly. These four environment variables and config options are what I would set before shipping any production agent workflow that runs unattended for more than a few minutes.</p>
<p><strong>1. Concurrency limit.</strong> <code>CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS</code> defaults to 20. For most tasks, 5 to 10 is more than enough and keeps costs predictable. Set this below 20 unless you actually need full parallelism.</p>
<p><strong>2. Spawn depth.</strong> <code>CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH</code> defaults to 3. If your architecture does not need deeply nested agents, setting this to 1 or 2 eliminates an entire category of accidental runaway spawning. Setting it to 1 disables nesting entirely -- subagents cannot spawn subagents.</p>
<p><strong>3. Budget per background session.</strong> <code>--max-budget-usd</code> on any <code>claude</code> background session invocation. This was broken before v2.1.217 -- it is enforced now. Set a per-run ceiling. Even 0 or 0 per task run is enough to catch runaway context growth before it becomes a 7,000 problem.</p>
<p><strong>4. Gateway spend limits (if applicable).</strong> If you are running through an enterprise gateway, configure per-developer or per-team daily caps and make sure your gateway is on v2.1.225 to surface the reset-time messaging. The average enterprise developer runs 50 to 50 per month; 90% stay below 0 per active day. If someone is trending above 0/day consistently, it usually means an unintended background session is still running.</p>

Pinning to an earlier version than v2.1.217 leaves you with unenforced budget flags.</p>

<h2>FAQ</h2>
<h3>Was the 200-subagent cap removed in today's releases?</h3>
<p>No. The 200-subagent-per-session spawn cap was removed in v2.1.221, which shipped August 4, 2026 -- four days before today. Today's releases (v2.1.225 and v2.1.226) added gateway spend-limit visibility and bug fixes. The subagent cap removal and the spend-limit improvement are separate changes that landed in the same week.</p>

<h3>What limits still apply after the 200-subagent cap was removed?</h3>
<p>Two limits remain active. Concurrency is capped at 20 simultaneous subagents by default (configurable via <code>CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS</code>). Spawn depth defaults to 3 levels (configurable via <code>CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH</code>). The per-session total limit is gone. Token budget is now the effective ceiling on how many subagents a session can spawn over its lifetime.</p>

<h3>Do I need a gateway to use the new spend-limit feature in v2.1.225?</h3>
<p>Yes. The spend-limit messaging in v2.1.225 surfaces caps set by an enterprise AI gateway, and requires the gateway itself to be running v2.1.225 or later. If you are hitting Anthropic's API directly without a gateway layer, the feature has no cap to surface. Native per-session spend limits without a gateway are not yet available in Claude Code.</p>

<h3>If I run 20 parallel subagents, what does that cost per day?</h3>
<p>At Claude Code's reported average of 3 per developer per active day on a single session, 20 simultaneous subagents would theoretically run at up to 60 per developer per active day -- though real-world tasks do not saturate concurrency continuously. The 0 to 30 per day estimate for 5 to 10 parallel agents is a more realistic range for sustained parallel workloads. Set <code>--max-budget-usd</code> on any session running unattended to cap exposure.</p>
